# 共用工作流与 Skill 接入设计

## 目标与权威来源

Windows 项目使用一份研发方法和模块知识。Claude Code 与 Codex 可分别承担 AI、UI、Ability 等模块，但按共同工作流、接口与验证约定交付。本工具负责知识入口，不提供多会话调度、工作区锁或业务流水线。

- `.claude/CLAUDE.md`：所有任务适用的工作流。
- `.claude/skills/<name>/SKILL.md`：唯一模块 Skill 正文。
- 项目已有文档：设计、接口、决策和验证事实，按需引用。
- `AGENTS.md`：Codex 读取共同工作流的入口。
- `.agents/skills/<name>/SKILL.md`：Codex 可发现的模块入口，仅含元数据和原文定位。

Claude 的设置、hooks 与工具权限不通过 Markdown 自动变成 Codex 配置。共同规范不保证模型推理完全一致；通过实际文件读取、交付和验证核对行为。

## 模式与范围

初始化仍仅创建两个共同入口。拆解依据职责和复用价值创建模块正文及发现入口。接入与维护面向已有项目，保留既有正文，只做获授权的增量变更。

用户明确请求接入现有 Skill 即授权机械创建对应入口；新增模块知识或改变公共研发方法仍按当前具体授权处理。已覆盖的操作不重复询问。未知手工文件、名字冲突、半套入口或两份正文分叉需要列出差异，不能批量覆盖。

模板和路径规则只维护在分发 Skill 的 [references/shared-skills.md](../skill/bootstrap-project-workflow/references/shared-skills.md)，安装器会递归复制它。

## 知识随交付更新

具体修改进入任务记录或 devlog；模块行为、接口与制作方式变化进入对应 Skill／引用文档；共同行为变化进入 CLAUDE.md。沿用已有目录，不给每次小改造一份新文档。真实证据和未验证边界一起记录，不把计划或猜测写成已有能力。

在得到提交授权时，代码和对应知识纳入同一交付。独立工作区核对规范版本，公共约定需落盘同步，不能假定聊天自动共享。

## 分发与升级

两个 PowerShell 安装器共用 `skill/bootstrap-project-workflow`，目标存在时不覆盖。本次不增加升级安装器；拉取仓库只更新源，已安装副本需要明确的本机更新操作。项目生成的入口随项目提交，其他人消费这些项目规范不需要安装 Bootstrap。

## 验证

1. Skill 格式和必要字段。
2. 临时目录安装复制完整且不覆盖已有目标。
3. 薄入口相对路径、原文引用解析，以及复制到另一目录后仍有效。
4. 接入前后差异与重复执行不修改同样内容。
5. 真实 Claude／Codex 发现、实际原文和引用读取另行核验；未运行就明确写未验证。

本次变更没有业务代码，也不需要项目构建。不会启动多代理循环、改造公司项目、写第二大脑正文或操作真实游戏资产。
