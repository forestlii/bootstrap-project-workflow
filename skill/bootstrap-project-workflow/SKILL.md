# 初始化、拆解与维护项目工作流

## 核心原则

Claude Code 与 Codex 共用一份工程方法、模块知识和验收约定：

- `.claude/CLAUDE.md` 是共同工作流；`.claude/skills/<name>/SKILL.md` 是模块 Skill 正文。
- 原有设计、接口、决策和验证文档保留在项目约定位置，由 Skill 引用，不搬运或复制正文。
- 根目录 `AGENTS.md` 是 Codex 的薄入口；项目级 `.agents/skills/<name>/SKILL.md` 是 Codex 可发现的薄 Skill 入口。
- 薄入口只保留名称、触发描述、原文定位与读取要求，不发展第二套业务规范。
- 每次实质修改留下知识记录；更新既有 Skill 或引用文档优先，不为每次修改新增 Skill。

本 Skill 只处理项目工作流和知识接入，不因此获得业务代码、构建、部署或仓库发布权限。用户已明确授权的当前范围无需重复确认；未覆盖的操作仍按项目规则处理。

## 选择模式

先确认 Windows 环境与用户指定的项目根目录，不因当前目录方便就操作另一个项目。

| 用户意图／现状 | 模式 |
|---|---|
| 初始化工作流，两个入口均不存在 | 初始化 |
| 拆解／分析项目，两个入口均不存在 | 先初始化，本轮不顺手创建业务 Skill |
| 拆解／分析项目，两个入口齐全 | 拆解 |
| 接入 Codex、建立 `.agents/skills`、统一 Claude/Codex、维护已有规范 | 接入与维护 |
| 只存在一个入口或已有内容互相矛盾 | 报告差异；仅在明确的修复授权范围内补全 |

只询问影响当前操作且无法从项目或既有决定确认的信息。不把“分析项目”扩展成实现业务功能。

## 初始化模式

### 1. 只读检查

检查 `.claude/CLAUDE.md` 与 `AGENTS.md`。任一已存在时不覆盖，报告现状；用户明确要求改造已有入口时改走接入与维护模式。

只读 README、现有规则、目录、项目清单、框架入口和构建脚本。跳过依赖、缓存、构建产物和大型生成目录；不运行安装、构建、测试或项目程序。区分文件证实的事实与待确认信息，不编造项目架构。

### 2. 起草两个入口

仅起草 `.claude/CLAUDE.md` 和 `AGENTS.md`。共同工作流包含：

- 项目概览、代码结构、构建与验证、开发流程、项目约束、项目 Skill。
- 已确认的环境、命令与模块入口；未确认的内容明确标注。
- 需求理解、方案审核、实施和验证的边界，沿用负责人现有授权。
- 所有任务必须遵守的共同规则放在此处，不依赖某个 Skill 恰好被选中。
- 后续 Skill 拆解与知识回写使用下文“知识回写规则”；只按任务加载匹配正文。

`AGENTS.md` 使用以下语义，不复制项目事实：

```markdown
# 项目 Agent 入口

- 开始任务前，完整读取并遵守 `.claude/CLAUDE.md`。
- Claude Code 与 Codex 共用 `.claude` 中的规范及其引用文档。
- `.agents/skills` 是 Codex 发现入口，业务正文在 `.claude/skills`。
- 选择匹配的 Skill 后完整读取其原文；尚无发现入口时，通过 `.claude/skills` 的名称与描述选择原文。
- 引用文件相对于声明引用的原文件解析，不相对于转接入口或终端目录。
- 按共同工作流回写知识；遇到冲突、缺失或未授权范围时明确报告。
```

### 3. 写入与交付

展示准确路径和完整草稿。没有具体写入授权时等负责人批准；已有同范围明确授权时直接执行，不反复询问。

写前复核冲突，只创建两个获批文件及必要的 `.claude` 目录。初次初始化不创建业务 Skill、`.agents/skills`、模板、锁文件或同步工具。

报告实际写入结果与未验证项。不自动构建、测试、提交或推送。部分失败时保留现场，不擅自清理。

## 拆解模式

1. 读取共同工作流和已有 Skill 的名称、描述，识别现有边界；不一次加载全部正文。
2. 只读主要代码结构、入口、框架依赖和相关已有文档；不运行项目程序或修改代码。
3. 按可复用职责拆分，展示候选名称、触发条件、范围、来源、暂不拆分的内容；不按目录机械造 Skill。
4. 按现有授权确认候选范围，逐个读取必要来源并起草正文。一个 Skill 覆盖一个清晰模块，记录制作方法、接口、约束、参考实现和验证入口；大段细节引用既有文档。
5. 新建项目 Skill 的交付包含正文和同名 Codex 薄入口，文件清单中必须列明两者。入口结构见 [references/shared-skills.md](references/shared-skills.md)。已有正文仅需接入时进入接入与维护模式。
6. 展示具体草稿和文件清单；授权覆盖后仅写这些文件。候选讨论本身不是任意写入授权。
7. 按“验证与交付”核对知识接入；不得借此启动业务构建或修改其他模块。

## 接入与维护模式

这是对已有项目的增量接入，不重新初始化，不复制或重写整个知识库。

1. 读取两个共同入口、已有 `.claude/skills` 元数据和 `.agents/skills` 的现状；发现名称重复、目录与 name 不匹配、断链或正文分叉时先列明。
2. 明确哪些是待接入 Skill，哪些是已有独立 Codex Skill；未知文件和手工正文保留，不批量覆盖或删除。
3. 对每个纳入范围的 Skill，复用其有效名称与触发描述，在 `.agents/skills/<name>/SKILL.md` 建薄入口；只读匹配任务所需的正文和引用。
4. 使用普通文本文件和相对路径，随 Git／P4 交付；默认不创建 symlink、junction，不记录机器绝对路径，不复制 Claude 专用权限、hooks 或 tools 配置到 Codex。
5. 比对已有薄入口：完全一致则不改；仅名称、描述或目标变更时最小更新。重命名、删除或存在手工内容的入口，明确列入变更范围，不自行清理。不得产生两个同名 Codex 入口。
6. 用户要求维护共同规则时，以最小差异更新入口与回写规则，保留现有项目约定。用户明确要求“为现有 Skill 建立 Codex 入口”已授权这项机械接入，不需要逐文件再次批准。
7. 知识正文变化只改正文；元数据变化同步薄入口。功能没有变化时，不为接入任务发明业务事实或新模块。

薄入口模板与相对路径规则见 [references/shared-skills.md](references/shared-skills.md)。

## 知识回写规则

将以下规则纳入共同工作流；日常研发按已授权范围执行，不要求每次小修重新运行 Bootstrap。

| 实质修改 | 知识落点 |
|---|---|
| Bug 修复、参数调整、局部实现 | 当前任务记录／devlog：修改、原因、验证、遗留事项 |
| 模块行为、接口、配置或验收方式改变 | 更新对应模块文档，并检查 Skill 的事实、链接和操作步骤 |
| 可复用制作方法或模块约束改变 | 更新已有 Skill；名称或触发范围变更时更新 Codex 入口 |
| 新增独立模块 | 按拆解流程创建 Skill 正文和发现入口 |
| 所有 Agent 的研发方式改变 | 更新 `.claude/CLAUDE.md`；`AGENTS.md` 仍只转接 |

- 沿用项目已有文档目录；已有任务记录中追加，不为每次修改新建一篇文档或一个 Skill。
- 记录事实、已决定的接口、修改理由及真实验证结果；不保存模型隐式推理，不把猜测写成规则。
- 交付中列出更新的知识文件；若 Skill 不受影响，在任务记录说明，不强行改正文。
- 已授权功能变更中必要的事实性文档回写一起完成；新增模块边界或改变团队方法须按现有授权与审核规则处理。
- 代码和相应知识进入同一可追溯交付；这不自动授权提交或推送，按当前任务已有授权执行。
- 独立工作区／会话开工前核对共同规范版本；公共决定落盘并同步后再依赖。聊天内容不会自动跨会话共享，也不擅自同步或覆盖其他会话工作区。

## 验证与交付

接入任务至少检查：

- 每个入口有有效 YAML `name`／`description`；与原文一致，名称唯一。
- 相对路径从入口文件目录出发可解析到项目内预期正文；正文引用继续以原文目录解析。
- 缺失源文件时报错，不生成替代正文；对已有未知内容不覆盖。
- 同样内容重复接入无变化；普通拉取后的独立目录仍可解析，不依赖个人全局 Skill 或绝对路径。
- 在可用的 Claude／Codex 新会话中选择一个实际模块，核对发现结果、打开的正文路径和必要引用。发现未刷新时重启再查；不能仅凭 Agent 声称“已遵守”认定成功。

文件结构验证与真实客户端发现分开报告。未运行的客户端、业务构建或 UE 流程必须标为未验证。仓库文件更新不等于用户安装目录、其他工作区或已开启会话自动更新。

## 边界

不复制两套正文，不批量覆盖未知入口，不预设 Unity／Unreal 业务知识，不启动多代理循环，不扩展业务实施、验证或发布权限。文档规则指导行为，关键工程约束仍需项目自身检查和验证。
